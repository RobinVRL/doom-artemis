# Lua Doom for Artemis / Switch 2

An adapter of Wagner Nunes da Silva's [lua_doom](https://github.com/vagucs/lua_doom),
pinned to commit `2dba03148ea6640a3ea151862ee3073cb307149a`, for the existing
Seedsow Artemis Lua 5.1 launcher. The renderer, maps and game logic run locally
in Lua. SDL2 and desktop DLLs are not required.

See the [setup guide](SETUP.md) for the upstream checkout, shareware WAD and
installation steps. The installer uses `exploitb.lua` and `exploitb2.lua` by
default. Pass `--dialingspoon` for the `ax_` filenames.

**Status:** tested under plain Lua 5.1 on the host, including real shareware
E1M1 rendering, movement, pistol fire, menus, saves, doors and golden pixel
fixtures. E1M1 has run on the Switch 2 with confirmed movement, turning,
firing and menu controls. The final tested payload was read back and committed
as both slot-B scripts. Press B in the launcher to start it.

The payload is `dist/doom.lua`. The build creates identical copies under
both launcher naming schemes. It expects the shareware
IWAD at `save:/doom_iwad.wad`. The source WAD was downloaded from
https://raw.githubusercontent.com/Daivuk/PureDOOM/master/doom1.wad.
Commercial game data is not included.

Build and verify from the project folder.

```powershell
py build.py
py -m pip install lupa
py tests/test_port.py
py tests/run_upstream.py
py tests/render_preview.py
```

Tests use Lupa's Lua 5.1 runtime. The
13 upstream regression scripts run with the actual patched engine modules;
the Windows-specific temporary directory setup in the save test is redirected
inside the workspace. `verification/e1m1.png` and `verification/firing.png`
are generated by the actual engine in the offline smoke run, not console captures.

The generated script uses private module loaders and leaves `package.path`
and the game's global `game` table intact. Initialization waits for the next
Artemis frame. When an HTTP frame handler is already running, it is pumped
after each Doom callback. Minus, quit, input errors and rendering errors stop
the coroutine, release the loaded world and return control to HTTP. Without
an existing HTTP handler, Minus leaves an idle screen; restart the game for
the launcher.

Default controls:

- A: fire in game; confirm in menus.
- B: use in game; back in menus.
- X: cycle owned weapons. Y: automap. Minus: stop.
- Left stick: move forward/back and strafe. Right stick: turn.
- D-pad: move forward/back and turn, or navigate menus. Plus: menu.
- L/R: strafe. ZL: run. ZR: fire.

Stick, Plus and shoulder codes were recorded from the actual Joy-Cons. All
codes can be replaced through `doom_config.bindings` before including the script.

Current limitations:

- No audio backend; sound and music are disabled.
- Each changed framebuffer is encoded as an indexed PNG in one of two temporary
  save files. The reserved layer is released before `e:unbindSurface(path)`
  invalidates its surface. Low-detail rendering, cached plane calculations and
  faster PNG encoding improve speed, but playback is still choppy. In the
  sampled E1M1 scene, 42 frames were presented over 8 seconds (5.25 FPS).
- Without an external clock the game estimates callback duration from whole
  wall-clock seconds. The same sample advanced 286 simulation tics (35.75/sec).
  Timing is approximate and capped after stalls. A launcher can supply a
  monotonic millisecond function as `doom_config.clock_ms`.
- Doom saves use `save:/doom_save<slot>.dsg`; gameplay does not commit the mount
  every frame. Persistence of game saves needs a commit by the launcher.

Optional configuration:

```lua
doom_config = {
    iwad = 'save:/doom_iwad.wad',
    warp = true, -- directly enter shareware E1M1; default is the title/menu
    scale_x = 4,
    scale_y = 3.6,
    -- detail_level = 0, -- high detail, slower than the default low detail
    -- Default native offsets are 480,260 to compensate center-based scaling.
    -- left = 480,
    -- top = 260,
    -- verbose = true, -- otherwise startup messages stay in doom_status.logs
    -- clock_ms = your_monotonic_clock,
    -- invalidate = your_image_cache_invalidator,
    -- bindings = {A=13,B=27,X=112,Y=113,MINUS=114,PLUS=115,
    --             L=116,R=117,ZL=118,ZR=119,LEFT=37,UP=38,RIGHT=39,DOWN=40,
    --             LS_LEFT=193,LS_UP=194,LS_RIGHT=195,LS_DOWN=196,RS_LEFT=197,RS_RIGHT=199},
}
```

`deploy.py` backs up existing slot-B scripts, uploads and reads back the IWAD
and staged payload, checks syntax without execution, installs both authorized
slot-B filenames, and commits the save using the launcher's existing SDK API.
It never includes or launches Doom. Run it only when console upload is authorized.
The current device installation, backup prefix, and live sample are recorded
in `verification/device-release.json`. `verification/device-e1m1.png` is a
frame generated during the Switch 2 playtest.

This repository contains the adapter and build tools. The upstream checkout,
generated payloads, WAD, and local device records are ignored by Git. Upstream
files retain their author notices when used to build the payload.

The target's `math.atan(1)` was isolated as the startup-crash trigger. The
build generates the tangent-to-angle lookup table on the host, so the engine
does not invoke target `math.atan`. All 2,049 values match the original Lua
formula, and the golden renderer tests still pass.
